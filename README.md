# envgrep

[![CI](https://github.com/Woonnk/envgrep/actions/workflows/ci.yml/badge.svg)](https://github.com/Woonnk/envgrep/actions/workflows/ci.yml)

Find every environment variable your code actually reads, and keep `.env.example` honest.

No dependencies. One command. Works across Python, JavaScript/TypeScript, Go, Rust, Ruby, PHP, Java/Kotlin and shell.

---

## The problem

You clone a repo. You copy `.env.example` to `.env`. You run it. It crashes on a missing
variable that somebody added four months ago and never documented.

`.env.example` drifts because nothing enforces it. `envgrep` reads your source, finds every
variable your code touches, and tells you exactly where the example file is lying.

```
$ envgrep check
Missing from .env.example
  + STRIPE_WEBHOOK_SECRET  billing/webhooks.py:14, billing/verify.py:88
  + REDIS_URL              worker/queue.py:9

In .env.example but never read
  - LEGACY_API_TOKEN

2 missing, 1 orphaned. Run: envgrep sync
```

Exit code `1`, so CI fails before the reviewer has to notice.

## Install

```bash
pip install envgrep
```

Or run it without installing:

```bash
pipx run envgrep check
```

## Commands

| Command | What it does |
| --- | --- |
| `envgrep scan` | List every variable referenced, with file and line |
| `envgrep check` | Compare code against `.env.example`, exit `1` on drift |
| `envgrep sync` | Rewrite `.env.example` from what the code reads |
| `envgrep diff` | Show what your local `.env` is missing to boot the app |

### scan

```
$ envgrep scan
VARIABLE               DEFAULT      USED IN
---------------------  -----------  --------------------------------------------
DATABASE_URL                        api/db.py:12, api/migrate.py:4
PORT                   8000         api/server.py:31
STRIPE_WEBHOOK_SECRET               billing/webhooks.py:14

3 variables across 47 files
```

Defaults are pulled out of the code itself, so `os.getenv("PORT", "8000")` and
`${PORT:-8000}` both surface `8000`.

### sync

Rewrites the example file, keeping existing values and the comments above them, adding
what's new, dropping what no longer exists.

```bash
envgrep sync              # write it
envgrep sync --dry-run    # print what would be written
envgrep sync --keep-orphans
```

### diff

For the person who just cloned your repo:

```
$ envgrep diff
Required, not set in .env
  × DATABASE_URL
  × STRIPE_WEBHOOK_SECRET

Missing but defaulted in code
  ~ PORT=8000
```

## Use it in CI

```yaml
- uses: actions/checkout@v4
- uses: actions/setup-python@v5
  with:
    python-version: "3.12"
- run: pipx run envgrep check .
```

As a pre-commit hook:

```yaml
repos:
  - repo: local
    hooks:
      - id: envgrep
        name: envgrep
        entry: envgrep check
        language: system
        pass_filenames: false
```

## What it detects

| Language | Patterns |
| --- | --- |
| Python | `os.environ["X"]`, `os.environ.get("X")`, `os.getenv("X")`, plus `from os import environ` and aliased imports |
| JavaScript / TypeScript | `process.env.X`, `process.env["X"]`, `import.meta.env.X`, `Deno.env.get("X")` |
| Go | `os.Getenv("X")`, `os.LookupEnv("X")` |
| Rust | `env::var("X")`, `env!("X")`, `option_env!("X")` |
| Ruby | `ENV["X"]`, `ENV.fetch("X")` |
| PHP | `getenv("X")`, `$_ENV["X"]` |
| Java / Kotlin / Scala | `System.getenv("X")` |
| Shell | `$X`, `${X}`, `${X:-default}` |

Python goes through the AST rather than a regex, so `environ["SCRIPT_NAME"]` inside a WSGI
handler is correctly ignored — bare `environ` only counts when the file actually imported it
from `os`. Shell scripts skip variables the script assigns itself, so `ZIP=$(which zip)`
followed by `$ZIP` doesn't get reported as configuration.

## Configuration

Optional. Put it in `envgrep.toml`:

```toml
env_file = ".env"
example_file = ".env.example"
ignore = ["VITE_*", "npm_*"]
exclude = ["tests", "examples"]
header = "Generated by envgrep. Run 'envgrep sync' after changing config reads."
```

Or in `pyproject.toml` under `[tool.envgrep]`. Every key has a flag equivalent:
`--ignore`, `--exclude`, `--env-file`, `--example-file`.

`node_modules`, `.venv`, `dist`, `build`, `target`, `vendor` and friends are skipped by
default. Test directories are **not** — if you don't want test fixtures in your example file,
add `exclude = ["tests"]`.

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Clean |
| `1` | Drift found |
| `2` | Bad path or unreadable file |

Add `--json` to any command for machine-readable output.

## What it doesn't do

- Dynamic lookups. `os.environ[key]` where `key` is a variable can't be resolved statically, so it's skipped rather than guessed at.
- Secret values. It only ever reads variable *names* from source; it never prints the contents of your `.env`.
- Multi-line values in `.env` files.
